# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

ML Tech Games is a site of free, browser-only educational games for children, in Brazilian Portuguese. It is built with Astro and TypeScript, hosted on Cloudflare Workers static assets, and uses Firebase Auth and Firestore (project `mltechgames`) only for optional saved progress.

Product rules that drive design decisions:

- **Learning stays hidden.** The skill must be the game mechanic, not a quiz between rounds. Kid-facing text never mentions learning or school.
- **Play first.** Nobody needs an account to play, and anonymous players load no Firebase code and make no third-party requests. A test enforces this.
- **The account belongs to the adult.** Children are profiles inside it, identified only by an avatar from a closed list. This is how the site approaches art. 24 of the ECA Digital (Lei 15.211/2025). Never add children's names, ages, photos or any free-text field.
- **Free, with donations from adults.** Donations never give in-game advantages.

Every game must avoid loot boxes, purchases, chat or user-to-user contact, public rankings, notifications, autoplay and rewards for time spent (ECA Digital arts. 17, 20 and 21). Scores come from the client and can be forged, so a leaderboard would also need server-side validation. `src/pages/responsaveis.astro` tells guardians what the site stores and does not do: update it whenever that changes.

## Commands

```sh
npm run dev            # Astro dev server
npm run preview        # serve dist/ with Wrangler, as in production (run build first)
npm run build
npm run check          # type-check
npm test               # unit tests
npx vitest run tests/unit/pix.test.ts   # one file
npm run test:regras    # Firestore rules, in the emulator (needs Java)
npm run test:e2e       # Playwright + Auth and Firestore emulators (needs Java)
npm run deploy         # build and publish to Cloudflare
npm run deploy:regras  # publish firestore.rules to Firebase
npm run deploy:redirecionamento  # publish the web.app redirect to Firebase Hosting
```

CI (`.github/workflows/ci.yml`) runs every suite on each push to `main` and then publishes, but only when the repository has the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets: without them it warns and skips, and the site is published with `npm run deploy`. A failed e2e test shows up as an annotation on the run, and its Playwright trace is uploaded as an artifact.

To run one e2e test: `npx firebase emulators:exec --only auth,firestore --project demo-mltg "playwright test conta.spec.ts"`.

E2e tests run against a separate build in `.dist-e2e/`, created with `PUBLIC_EMULADOR=1`, served by Wrangler. Don't use `astro preview` for them: it detached into the background and made Playwright's web server exit. The Auth emulator's popup is driven for real, because popups have browser restrictions that hooks would hide.

## Architecture

Pages are static (`src/pages/`) and share `src/layouts/Base.astro`, which includes the header, footer and dialogs (`src/components/Janelas.astro`, behavior in `src/lib/interface.ts`). Its `voltar` prop swaps the logo for a back button, in the header so it costs no height on small phones. Any element with `data-abrir="<dialog id>"` opens that dialog.

`src/lib/firebase.ts` is the only entry point to Firebase, through dynamic imports. `src/lib/conta.ts` holds the account logic:

- `localStorage` is always the working copy of the active profile's progress, under `mltg:progresso:<jogoId>` (`src/lib/local.ts`). `mltg:ultimos` lists games started on this device, newest first (`moldura` marks it on start), and feeds the home page's "Continue jogando" strip; it is never synced and is cleared along with the progress. Firebase only loads on pages when the `mltg:sessao` marker is set, or when the login dialog opens.
- Firestore paths are `usuarios/{uid}/perfis/{perfilId}` (`{ avatar, criadoEm }`) and `.../progresso/{jogoId}` (`{ recorde, fase, atualizadoEm }`).
- On login, anonymous progress merges into the chosen profile with `mesclar` (`src/lib/progresso.ts`), which keeps the max of each field. Switching profiles clears the local copy so children's progress doesn't mix, and logout does the same for shared devices.
- Sync only writes what differs, so opening a page costs reads but no writes.

`firestore.rules` denies everything except an owner's own profiles and progress, and only lets `recorde` and `fase` go up. Avatar ids are duplicated between `src/lib/perfis.ts` and `perfilValido` in the rules, and a rules test keeps them aligned.

Browser popups must open directly from a click. Load the SDK before the click (`firebaseCarregado`), and don't put `confirm()` or other awaits before `signInWithPopup` or `reauthenticateWithPopup`.

The `apiKey` in `firebase.ts` is a Firebase web key, which is public by design.

`site` in `astro.config.mjs` is the public address, used by the share tags in `Base.astro`, `sitemap.xml` and `robots.txt`: change it if the site gets its own domain. `scripts/imagens.mjs` renders the share cards (`public/img/social/`, 1200x630, one per game plus `site.jpg`) and the home-screen icons with Playwright. The manifest uses `display: browser` on purpose, because a standalone window breaks the login popup.

Firebase Hosting only redirects `mltechgames.web.app` and `mltechgames.firebaseapp.com` to the site on Cloudflare (`firebase.json`). Redirects win over files, so `public-redirect/` is never served, and `/__/*` is reserved, so the login popup's `/__/auth/handler` keeps working on `firebaseapp.com`. Check that path after changing the redirect.

### Games

Everything a game shares lives in one place, so a change reaches all games at once and a new game only writes its mechanic:

- `src/lib/jogos.ts` is the single source of each game's id and texts. It is read at build time only: don't import it from browser code, or every game ships every game's text.
- `src/layouts/Jogo.astro` renders the page shell: header stats (`.placa`) and, below it, `.palco`, a one-cell grid holding `.cenario` (the slot for the game's scene) and `#painel`. The panel dims the scene and centers `.cartaz`, a card with the cover art, title and instructions in the static HTML. Because both share the cell, the stage grows when a card is taller than the scene, so a card is never cut. `.cenario` is isolated, so no scene z-index can cover the panel.
- `src/jogos/kit/` has the browser side. `moldura.ts` owns the start and end screens, record, saving, the login invite and redrawing after login or a profile change. `telas.ts` builds the HTML of the screens every game shows with `mostrar`: `telaFase` (three stars, the third only for a phase with no stumble, which each game defines), `telaNovidade` and `telaTropeco`. `tempo.ts` has `esperar` (respects reduced motion) and `criarLaco` (real-time loop with `dt` clamped between 0 and 50 ms: the first frame's clock can be behind the moment the loop was turned on, and a negative `dt` once froze Carteiro forever). `dom.ts` has `aoTocar` and `medirEmVolta`. `sorteio.ts` has `Rng`, `sortear` and `embaralhar` and is the only DOM-free kit file, so it's the only one `logica.ts` may import. `som.ts` synthesizes sound with Web Audio (`tom`, `chiado`, `melodia`), so there are no audio files or requests. Sounds only follow a child's action and there is no background music. `efeitos.ts` has throwaway visual effects (`flutuar`, `estourar`, `lancar`, `confete`, `animar`, `pular`, `tremer`), which are skipped under reduced motion. `moldura` owns the sound button and the end-of-game sound; each game's sounds live in its `sons.ts`.

`site.css` and `jogo.css` sit in the `compartilhado` cascade layer, so a game's unlayered `jogo.css` always wins. The build's CSS order can't be relied on: it changed just by moving an import into a layout.

Every game must fit a phone's visible height without scrolling the page, because a drag gesture fights with page scroll. A real phone shows about 640 to 700 px with the browser bars, which is what `tests/e2e/site.spec.ts` checks at 360x640 for every game. `--livre` (`jogo.css`) is the height left for the whole game below the header, and each scene limits itself by it. When what surrounds the scene changes height between phases, as with Submarino's cards or Caminhão's orders, `medirEmVolta(cena)` measures it into `--fora` and the CSS uses `calc(var(--livre) - var(--fora))`. On a phone lying on its side no game fits, so `.vire` covers the game and asks to turn it.

Keep the kit small: move code there when a second game needs it, or when it holds a rule every game must get right, like the three above. Mechanics stay in each game, including similar ones, because forcing games into one mold costs more than some repetition. The kit loads on every game page, so heavy libraries never go in it. A game with its own engine, like Phaser, still uses the layout and `moldura`, and draws inside the slot.

### Adding a game

1. Add it to `JOGOS` in `src/lib/jogos.ts`. The `id` is the progress key and the page path, so it can't change after publishing. Its `pratica`, `areas`, `habilidades` and `idade` (a suggested age range) feed the game guide on the guardians' page, which filters by area (`/responsaveis/#matematica`, `src/lib/guia.ts`); the home page links to each area only from its adults' section. Subjects and ages never go on the kid-facing cards. Add the card art at `public/img/jogos/<id>.svg` (640x400), which is also the cover on the game's start screen, and run `node scripts/imagens.mjs` to generate its share card in `public/img/social/`.
2. Put the code in `src/jogos/<id>/`, with the rules in a DOM-free `logica.ts` with an injectable `rng`, tested in `tests/unit/<id>.test.ts`.
3. Create `src/pages/jogos/<id>.astro` with `<Jogo id="<id>">` around the scene, importing the game's `jogo.css` and, in a `<script>`, its `jogo.ts`. Add heavy libraries such as Phaser only to games that need them, so they stay out of other pages.
4. In `jogo.ts`, call `criarMoldura({ aoComecar, aoSeguir })`. Use `placa` to draw, `salvar` at each phase, `mostrar` for the game's own screens (a button with `data-acao="seguir"` returns to the game) and `fim` to end. A game with a last phase passes `final` (title and HTML) to `fim` when it is beaten. Build those screens with `kit/telas.ts` so all games celebrate and console alike. A card grows up to the free height of the screen and scrolls from its title beyond that. Only use `aoMudarConta` directly for progress drawn outside the panel. Drag games track one pointer id and must release it on `pointerup`, `pointercancel` and `lostpointercapture`, or a gesture taken by the browser leaves the game deaf to touches.

`tests/unit/catalogo.test.ts` fails if a page, folder, test or share card is missing or isn't in the catalog. `tests/e2e/site.spec.ts` loops over `JOGOS`, so each new game is already checked for opening from the home page, starting, JS errors, third-party requests, bundle size and fitting a small phone. Only write e2e tests for what's specific to the game.

`src/jogos/monstrinho/` is the simplest reference: children tap falling numbers to reach the monster's exact hunger, which practices addition, and `proximaBolha` guarantees a usable number is always available.

`src/jogos/robo/` is turn-based on purpose, with no timer, because the point is planning. Limited charges add up against enemy defense, and enemies are generated by splitting the charges among them, so every phase is solvable. Balance is tested: `tests/unit/robo.test.ts` simulates simple strategies and requires that "biggest that fits" stops being enough in high phases. Returning charges on exact hits made that strategy always win, so keep exact hits as points only.

`src/jogos/submarino/` is the most complex one: children assemble a route from cards, then watch it run, and a failed route stays on screen to be fixed. `rodar` in `logica.ts` is a small interpreter that returns every step, and `jogo.ts` only animates them. Phases are generated from a secret route whose trail becomes the map, so every phase is solvable. `gerarFase` rejects maps where the route would fit in the slots as plain moves, which is what makes the new card necessary. Only crashes cost a life: fixing mistakes is the game, so running out of treasure or walking in circles is free, and the map never changes between attempts. The 🔁 block is drawn in place of its card inside the route, so children see what comes before and after it, which is why a route holds only one. ⭐ stays in its own box because it can be used several times.

`src/jogos/boiada/` is turn-based: children choose gates that change the herd's size, and the herd must reach the wagon's goal at the end of the road. A gate that isn't chosen stays on the road, and this rule is what makes the game work. All four operations preserve order, so with independent gates "biggest herd now" would always be optimal. Keeping the unused gate makes order matter, which is why adding before multiplying wins. `gerarFase` draws roads without repeated gates and checks every path with `explorar`, rejecting any screen with no gate that grows the herd, because a screen of only − and ÷ reads as a dead end. Up to `ULTIMA_FASE_FACIL` the goal is within reach of "biggest now", and after that it's above it, which `tests/unit/boiada.test.ts` enforces along with a learnable rule beating random play. Tests must pass a seeded `rng`, because `passar` draws the next phase and a constant one makes `gerarFase` loop forever. Gates are buttons on the road inside the scene, one per fork drawn by `desenharVias`, so `TOPO_DAS_PORTEIRAS` and `ALTURA_DAS_PORTEIRAS` must match `.porteiras` in `jogo.css`. Only the sign pulses, because a moving button makes taps miss and Playwright wait forever. The scene uses `isolation: isolate` so its z-indexes can't cover the panel, and `.tropa` has `pointer-events: none` because it sits above the gates.

`src/jogos/salto/` is the number line game: children read a number, stretch an elastic and release where they think it sits on a ruler that only labels its ends. The target stone is not in the DOM until the astronaut is in the air, because a visible stone would turn estimation into plain aiming, and the shadow never shows a number for the same reason. Reached stones stay lit and become the references, while the unlabeled ticks of early phases fade out. The elastic stretches toward the finger instead of backward like a slingshot, because at 0 there is no room behind the astronaut on a phone, and the shadow sits above the finger so the hand doesn't cover the ruler. All distances are fractions of the ruler (`pos`, 0 to 1), so one aim works for every scale, and the stone's drawn width is its real hit area. `saltar` checks the target first, then releasing on the current stone (cancels), then other lit stones (safe and free), then the edge, then the crater. A crater costs a heart and leaves the stone revealed until reached, for no points. New rulers are explained by `NOVIDADES` in `jogo.ts`. `tests/unit/salto.test.ts` requires a rough estimate to win every phase while always aiming at the middle or guessing fails. The astronaut is centered with `transform` because the flight animates `translate`, and `.pista` ends at the ruler's height so everything on it is positioned along its width.

`src/jogos/garcom/` is the English game: children read a monster's order, build a tray from the shelf and ring the bell. There is no voice and no timer, because the browser's speech voices can run on remote services and reading another language takes time. Words live in `cardapio.ts`, where each item's `fase` is the phase that introduces it and drives the new-words panel. The shelf never shows words, because matching letters would skip comprehension. `novoPedido` in `logica.ts` picks a generator by the phase's `tipos`, so comprehension grows through numbers, colors, negation, order, mind changes, needs and riddles. Traps named in a sentence (`armadilhas`) must stay on the shelf, or "tap the word you recognize" would always win. Missing items are free, because what's on the tray was right. Wrong items cost a heart, keep the order on screen and return in later orders through `reforco`. `montarPrateleira` shows exactly one right answer per line.

`src/jogos/minhoca/` is the literacy game and the only one where logic runs every frame, so `passo` mutates the state instead of copying it. The head steers toward the finger with a capped turn rate, and `RAIO_DA_CURVA` must stay below `ALCANCE_DA_BOCA` or she orbits a letter without reaching it. The body follows `rastro`, and `pontoDoCorpo` interpolates it so slow movement doesn't stutter. `kit/efeitos` animates `scale`, which multiplies a `transform`, so `.gomo` and `.cabeca` hold the position and `.bola` and `.rosto` take the animations. Words live in `palavras.ts`: `[certo|isca]` marks a trap and counts as one slot, even for CH and SS, because otherwise counting slots gives the answer. Each trap group needs words on both sides, or "always pick S" would win. The garden only holds `opcoes` letters and `repor` guarantees the right one and the bait. A wrong letter only counts when the finger is on it (`ALCANCE_DO_DEDO`): bumps on the way are free, since a bot that could spell lost up to three hearts per phase when they counted. Biting only counts while guided, because alone she turns over her own body, and the fence never hurts, so a released worm is always safe and children can stop to think. Up to `ULTIMA_FASE_MANSA` she rests when she arrives and nothing costs a heart. `vistas` carries the words already shown across phases and restarts, so `escolherPalavras` only repeats after the pool runs out, oldest first, and it lives in memory because progress only stores `recorde` and `fase`. A missed word returns once, at most one per phase: more than that made the game feel repetitive. Pick emojis from Unicode 12 or earlier, with one obvious name. `tests/unit/minhoca.test.ts` plays whole phases: spelling must win and going for the nearest letter must not.

`src/jogos/cerca/` is a Shikaku puzzle: children drag a rectangle around each animal to match the area on its sign, until the pasture is covered. The drag shows only the sides (`3 × 4`), never the total, because multiplying is the point. `gerarFase` splits the pasture into rectangles, then `resolverSemChute` only accepts maps where some animal always has exactly one place left, which also proves the solution is unique. `duvida` in `FASES` rejects maps that solve themselves, and `menor` keeps pieces of 2 and 3 out of high phases because those have a single shape. Only a wrong size around exactly one animal costs a heart, and not up to `ULTIMA_FASE_MANSA`. An empty drag, two animals or crossing a fence is free. A tap opens a fence for free, so points only land at the end of the phase, or reopening would farm them. Any fence of the right area stands, even in the wrong place: `semLugar` warns when that strands an animal. Fence and sign elements have `pointer-events: none`, so the pasture computes every cell from the pointer. Don't remove `container-type` from `.pasto`: `.bicho` sizes itself from `cqw`.

`src/jogos/luz/` is a Net puzzle: children rotate wires to connect the power plant to every house. `gerarFase` grows a random tree from the sources, turns leaves into houses and only then scrambles it, so giro 0 is always a solution. `bracos` is a 4-bit mask, clockwise from the top, and `girado` rotates it. Houses have no arms: any live wire pointing at one feeds it, and current never passes through it. Tap limits start after `ULTIMA_FASE_MANSA` because without them tapping until it works beats imagining the rotation, and `tests/unit/luz.test.ts` requires random tapping to fail. `mapa.menor` counts taps to the generator's solution, and another solution can beat it, so the bonus check is `<=`. A factory is a leaf that also gets an arm from a second neighbor wire of the same tree, which is why factories need two feeds. A battery's `carga` is the exact number of houses in its own tree, and exceeding it lights nothing. Touching the plant's network just merges with it. `voltas` in `jogo.ts` only grows, so a wire never spins backward from 270° to 0°. Buildings are `<symbol>`s drawn through `<use>`, so a selector like `.acesa .predio-janela` never matches: state reaches them only through inherited custom properties such as `--janela`. Switches were left out on purpose: in a tree, turning them all on would always win.

`src/jogos/pizza/` is the fractions game: a customer orders something like `1/2 verde + 1/4 vermelha`, children pick a cut, pick a flavor, drag across slices and ring the bell. It replaced a version where children fitted slices from a conveyor into pans, which had no goal that gave fractions meaning, so don't bring that back. The cut is the mechanic: `cortesQueServem` lists the cuts where every fraction becomes whole slices, so two fractions need a common denominator without the game ever saying so. Sizes are parts of `INTEIRO` (24), which every cut in `CORTES` divides. There is no 24 cut, so `gerarPedido` rejects orders like 1/6 + 1/8. Slice position doesn't matter and uncovered slices stay plain, so `conferir` only compares amounts. There is deliberately no "correct" mark before serving, because a tick would turn it into trial and error. A wrong pizza stays on the table to fix. Up to `ULTIMA_FASE_MANSA` it costs no heart, and those phases also come cut. A fresh cut clears the pizza for free. `moldes` in `FASES` hold denominators, and phases with a single cutter set `equivalentes`, which allows labels such as 2/4. The drag's first slice decides whether it covers or clears (`pincel`). Slices are found by angle from the center, not by hit-testing, so a finger that strays outside the pizza keeps working. Each flavor has its own topping shape so color isn't the only cue.

`src/jogos/torta/` is the reading and deduction game: suspects stand in a line, the sheriff's notebook shows clues such as "não estava ao lado de nenhum gato", and children tap whoever the clues clear. Clues arrive in `etapas`: the next one only appears once everyone the visible clues clear has been released, and every stage before the last leaves someone uncleared, which is what stops tapping everyone. Releasing a suspect the visible clues don't clear costs a heart after `ULTIMA_FASE_MANSA`, whether or not it's the culprit, so a refusal never reveals who did it. Released suspects stay in place, faded, because position clues (`ponta`, `vizinho`) refer to the original line. `gerarCaso` requires one culprit, every clue to clear someone still in line and the phase's `novidade` type to appear, and prefers clues that don't imply each other (`contida`). An `ou` clue is only generated when nobody in the line has both things, so inclusive and exclusive readings agree. `desenho.ts` builds each suspect's SVG inline without ids. `restoDaPista` is the clue without "Quem comeu a torta", which the notebook writes once.

`src/jogos/passarinhos/` is the music game: wires are a staff, each column holds one bird, a higher wire is a higher note, and children rebuild a melody they hear with Ouvir. The first bird comes placed as the pitch reference, because the skill is relative pitch. Tapping a placed bird makes it sing again instead of removing it, so children can compare notes freely. Rests (from phase 5) are a ground row: `Pouso` is a wire, `"chao"` or `null` (undecided), and `podeCantar` needs every column decided. A wrong song marks the wrong columns with "?" without telling the right wire, and costs a heart after `ULTIMA_FASE_MANSA`. `tests/unit/passarinhos.test.ts` requires the best non-listening strategy (guess, then change only the marked columns) to fail. `ESCALAS` never contains an octave, which sounds like the same note. Playback uses plain timers, not `esperar`, because reduced motion must not change the rhythm. The class is `.pauta`, not `.grade`, which `site.css` already uses for the home page cards.

`src/jogos/carteiro/` is the gravity game: children drag from the astronaut toward where the package should go (stretching toward the finger, like `salto`), release, and planets bend the path. `voar` in `logica.ts` is a fixed-step simulation that returns the points, so the same shot always takes the same path and `jogo.ts` only animates them. `gerarFase` sweeps `ANGULOS` × `FORCAS` shots and only accepts skies where each target's hit rate is within `acerto`, and, in `curva` phases, where aiming straight at the target fails. The cheap `acertaReto` check runs before the sweep, and the sweep stops once a target is too easy. `tests/unit/carteiro.test.ts` also requires a one-degree aiming tolerance and that random upward shots don't clear three phases in a row. When the remaining packages can't cover the remaining targets, a heart is lost and the same sky returns with the trails. `lancar` marks the phase `concluida` and `passarDeFase` draws the next one after the celebration, so the verifier never stalls a launch. Planet masses aren't to scale but keep the real order, and each `NOVIDADES` fact must be true.

`src/jogos/caminhao/` is the geography game: children tap a neighboring state to drive there, picking up and delivering orders with a fuel limit. `contornos.ts` holds the IBGE state outlines, projected and simplified, and is only read by the page at build time, so the map costs no JavaScript. `estados.ts` has names with their articles (`doEstado`, `paraOEstado`), regions, capitals, centers and neighbors taken from the IBGE mesh, and a test keeps neighbors symmetric. `menorRota` is a BFS over the truck's state and each order's `Situacao`, and the tank is the shortest route plus `folga`. Once the fuel left can't finish (`daParaChegar`), the trip restarts at once and costs a heart after `ULTIMA_FASE_MANSA`. Phases remove help in order: map marks, then siglas on the map, then the order names the capital. `planejar` phases reject trips where doing one order at a time fits in the tank. A tap near a small neighbor such as SE or DF counts for it (`escolher` samples around the finger with `elementFromPoint`), so labels, marks and the truck must keep `pointer-events: none`. `#estrada` exposes `data-posicao` for the e2e tests.

`src/jogos/corrida/` is the money game, designed with an 8-year-old: children drive a top-down car with car-relative arrows: up accelerates, down brakes and reverses, and the sides turn the wheel (keyboard, or an on-screen pad that reads the finger's angle, so up and a side work together). An earlier version steered toward the pressed direction, and the kid found it wrong. They pick up money and buy cars and equipment in a garage, up to flying cars. Each straight has a pair of money piles, one on each side of the road, and touching one makes the other vanish, so only counting pays. `gerarPar` in `dinheiro.ts` only draws pair types that fool shortcuts: the richer pile either has more pieces but not the most valuable one, or fewer pieces and the most valuable one, and coins are drawn at their real relative sizes, so the 25 looks bigger than the 50. `tests/unit/corrida.test.ts` requires "more pieces" and "highest piece" to stay near chance. Driving through the middle picks nothing, and touching an obstacle only slows the car, because the kid asked for crashes to get in the way as little as possible. Race phases need a podium finish, and solo phases can't be lost. Rivals follow `linha`, which bends away from obstacles, and they never collide with anyone. The test bot must win each race with the phase's `carro`, still reach the podium when distracted, and lose with the starting car from phase 8 on, so the garage matters. The game ends after `ULTIMA_FASE` (25), a 4-lap grand final: passing it calls `moldura.fim` with `final` for the podium screen, and `encerrar` keeps `fase` at 25 so progress never offers a phase that doesn't exist. Money and garage live only in the run: progress still stores just `recorde` and `fase`, and continuing from a later phase starts with `verbaDaFase`, enough for that phase's car. The world turns into the sky when the player's car flies, and rivals fly too. Tracks are rounded polygons in `pistas.ts`. A soft wall keeps the car inside and lets it slide along, costing more speed when hitting it head-on, with slower grass between the asphalt and the wall. Before it, cars could cut across the infield, and a lap whose shortcut skipped more than `SALTO_MAXIMO` samples silently didn't count. `medirMuro` puts the wall as far as `MURO_DESEJADO` while keeping a gap between walls of stretches that are `LONGE_NA_VOLTA` apart, so no shortcut can skip a lap; the kid asked for the wall farther away, and the old Castelo track was too tight for that, so it became Bota. Drawing the wall as a stroke of width `2 * muro` matches the physics, which measures distance to the nearest centerline sample. Money piles sit on the curb, within reach of a car touching the wall, and `ALCANCE_DO_IMA` stays small so even the full magnet can't take a pile from the middle of the road.

`src/jogos/aviao/` is the world geography game: a letter names a country (by name, then flag only, then capital, in three laps over seven regions) and children tap where they think it is; the plane flies straight to the tap. An earlier version copied `caminhao`, flying only between neighbors with counted fuel, and the user found that illogical for a plane, so don't bring it back. Inside the country, or within `FOLGA_DO_DEDO` screen pixels of its border, scores `PONTOS_NA_MOSCA`; outside, points shrink with distance up to `RAIO_DOS_PONTOS` map units, and beyond it costs a heart after `ULTIMA_FASE_MANSA`. `jogo.ts` measures the distance (`isPointInFill`, then sampled border points) and `logica.ts` only scores it. After a miss the plane flies on to the right country, which stays revealed with its flag and name as a reference for the next letters. Every region map is 1000 units wide, so the radius is the same share of the screen, and `km` in `regioes.ts` turns units into the "uns 300 km" message. `mapas.ts` (build time only) and `regioes.ts` were generated once from Natural Earth 50m with an azimuthal equal-area projection per region. All regions are in the page's HTML and the game switches the `viewBox`. French Guiana, Western Sahara, Kosovo, Taiwan and Palestine are grey and never destinations; Somaliland and Northern Cyprus are merged into Somalia and Cyprus. Countries without one undisputed capital have no `capital` and stay out of capital phases. Labels, flags and the plane are sized in screen pixels through `u` and `--u`, since each region has its own scale, and `desenharRotulos` culls overlapping labels by priority. Flags come from flag-icons (MIT, license in `public/img/bandeiras/`); the ones with heavy coats of arms were rasterized into a small PNG inside the same `.svg` file.

## Conventions

User-facing text, code comments and identifiers are in Brazilian Portuguese. The exception is this file. Touch targets must be large enough for small hands, and tap handlers on moving elements use `aoTocar`, which acts on `pointerdown`.

`PIX_COPIA_E_COLA` in `src/lib/site.ts` and `public/img/qrcode-pix.jpeg` hold the same payload and must change together.
